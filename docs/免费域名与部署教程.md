# 免费网址与域名申请教程

本文以「回声聊天室」为例，说明如何获得一个可以从公网访问的免费网址，以及如何给聊天室绑定一个免费二级域名。

> 教程更新：2026 年 11 月。免费套餐、域名审批规则和页面按钮可能变化；涉及账号、DNS、套餐时请以服务商官网当时显示的信息为准。

## 先选适合你的方案

| 方案 | 最终地址示例 | 成本 | 适合场景 | 主要限制 |
| --- | --- | --- | --- | --- |
| Render 免费实例 | `https://echo-chat-room-xxxx.onrender.com` | 免费 | 公开演示、发给朋友 | 需要 GitHub；闲置可能休眠；内存数据会清空 |
| Cloudflare Quick Tunnel | `https://随机字符.trycloudflare.com` | 免费 | 本机临时演示 | 电脑必须开机；关闭进程后链接失效；每次地址会变 |
| is-a.dev 免费子域名 | `https://echo-yourname.is-a.dev` | 免费 | 个人项目、作品展示 | 需要 GitHub 申请与人工审核；域名不由你独占控制 |
| 自购顶级域名 | `https://echo.example.com` | 每年付费 | 长期正式使用 | 需要购买和每年续费 |

如果你只是想让别人打开聊天室，**最快且最稳定的免费“网址”是 Render 分配的平台子域名**，不需要单独申请域名。

如果你想要一个更短的个性化域名，再继续看后面的 is-a.dev 教程。

## 三个容易混淆的概念

1. **域名**：例如 `example.com` 或 `echo.is-a.dev`，它只是一个地址名称。
2. **部署网址**：域名或平台子域名加上协议，例如 `https://echo.onrender.com`。域名本身不会自动运行网站。
3. **托管服务**：真正运行 Node.js 服务器的地方。本项目需要托管服务，而不是只上传 HTML 文件。

### 为什么不能直接用 GitHub Pages？

GitHub Pages 只能托管静态文件，不能运行 `server.js`。本项目需要后端提供：

- `/api/history` 历史消息
- `/api/events` 实时 SSE 推送
- `/api/messages` 接收消息

所以必须选择支持 Node.js 的平台，或者用一台保持开机的电脑配合隧道工具。

## 方案一：Render 免费部署 + 免费平台网址

预计时间：10～20 分钟。

### 第 1 步：准备 GitHub 仓库

需要一个 GitHub 账号。项目目前若还不是 Git 仓库，可以在项目目录中执行：

```powershell
cd "D:\desktop\gitee\聊天室"
git init
git add .
git commit -m "feat: add echo chat room"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

将尖括号中的内容替换成自己的 GitHub 用户名和仓库名。

第一次使用 Git 时，如果提交失败，可以先配置身份：

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

如果不熟悉 Git 命令，也可以在 GitHub 网页上新建仓库，然后通过「Add file → Upload files」上传整个项目文件夹中的文件。

### 第 2 步：注册 Render

1. 打开 <https://render.com/>。
2. 点击注册，建议使用 GitHub 登录。
3. 授权 Render 读取你选择的 GitHub 仓库。只需授权当前项目仓库也可以。

### 第 3 步：创建 Web Service

本项目已经包含 `render.yaml`，有两种创建方式。

#### 方式 A：使用 Blueprint（推荐）

1. 登录 Render 控制台。
2. 点击 **New + → Blueprint**。
3. 连接 GitHub，选择刚才的聊天室仓库。
4. Render 会读取 `render.yaml`，显示待创建的服务。
5. 确认套餐为 **Free**，然后点击 **Apply** 或 **Create**。

#### 方式 B：手动创建 Web Service

如果 Blueprint 没有识别到配置文件：

1. 点击 **New + → Web Service**。
2. 选择聊天室仓库。
3. 填写以下配置：

```text
Runtime:          Node
Build Command:    npm install
Start Command:    npm start
Health Check:     /health
Plan:             Free
```

4. 区域选择离访问者较近的位置，例如新加坡或离你最近的区域。
5. 不需要添加环境变量；Render 会自动提供 `PORT`。
6. 点击创建并等待构建、部署完成。

### 第 4 步：拿到免费网址

部署状态变成 **Live** 后，在服务详情页顶部可以看到类似下面的地址：

```text
https://echo-chat-room-xxxx.onrender.com
```

这就是 Render 免费赠送的平台子域名，可以直接发给朋友使用。

服务名通常会进入网址，创建时尽量取一个容易记住、全球唯一的名字。

### 第 5 步：验证部署

打开以下两个地址并替换成你的服务地址：

```text
https://你的服务名.onrender.com/
https://你的服务名.onrender.com/health
```

`/health` 应该返回类似：

```json
{"ok":true,"uptime":12}
```

然后打开两个浏览器窗口进入同一个频道，互相发送消息，检查实时同步和在线人数。

### Render 免费套餐注意事项

- 免费实例闲置一段时间后可能休眠，下一次访问需要等待冷启动。
- 免费实例重启、重新部署或更换实例后，内存中的聊天记录会消失。
- 本项目的消息历史只保存在内存中，没有数据库。
- 免费实例的连接数、运行时长和带宽受平台当前政策限制。
- 免费服务适合朋友间演示，不适合作为重要的长期生产服务。
- 如果 Render 创建页面已经没有 Free 选项，请不要误选付费套餐，可以改用其他支持 Node.js 的托管平台或本机隧道方案。

## 方案二：Cloudflare Tunnel 临时公网网址

如果你的电脑可以一直开机，或者只想临时把本机聊天室发给别人演示，可以使用 Cloudflare Quick Tunnel。它不需要域名，也不需要 Cloudflare 账号，会给一个临时的 `trycloudflare.com` HTTPS 地址。

预计时间：5～10 分钟。

### 第 1 步：安装 cloudflared

Windows 可以尝试 Winget：

```powershell
winget search cloudflared
winget install Cloudflare.cloudflared
```

如果 Winget 的包名已变化，请按 Cloudflare 官方文档下载 Windows 版 `cloudflared.exe`。

安装后重新打开一个 PowerShell 窗口，确认命令可用：

```powershell
cloudflared --version
```

### 第 2 步：启动聊天室

在第一个 PowerShell 窗口运行：

```powershell
cd "D:\desktop\gitee\聊天室"
npm start
```

确认本机可以打开 <http://localhost:3000>。

### 第 3 步：启动临时隧道

保持聊天室继续运行，在第二个 PowerShell 窗口执行：

```powershell
cloudflared tunnel --url http://localhost:3000
```

终端中会输出类似下面的临时地址：

```text
https://random-words-here.trycloudflare.com
```

这个地址可以从公网访问，并自动使用 HTTPS。

### 使用限制

- 只要本机、聊天室进程或隧道进程停止，网址就会失效。
- 每次重新启动 Quick Tunnel，地址通常都会变化。
- 电脑休眠、断网或防火墙阻断外连时也会失效。
- 这是临时演示工具，不适合长期公开运营。
- 不要把本机敏感文件放进聊天室公开目录，公开网址代表任何人理论上都能访问。

## 方案三：申请免费二级域名（is-a.dev）

如果你已经通过 Render 部署成功，并且想要一个比平台自动分配的网址更个性化的地址，可以申请社区维护的免费二级域名。

本文以 `is-a.dev` 为例。它提供的地址形式是：

```text
你的名字.is-a.dev
```

预计时间：提交申请约 10 分钟；审核和 DNS 生效通常需要数小时到数天。

> 重要：`is-a.dev` 不是传统域名注册商。域名由社区维护，申请人获得的是 DNS 记录使用权，不是可自由转移的资产。申请规则、禁止事项和模板可能变化，请以官网和仓库最新说明为准：
>
> - 官网：<https://www.is-a.dev/>
> - 注册仓库：<https://github.com/is-a-dev/register>

### 第 1 步：先完成 Render 部署

必须先把聊天室部署成功，拿到类似下面的稳定地址：

```text
echo-chat-room-xxxx.onrender.com
```

后面申请的免费域名会通过 CNAME 指向这个 Render 地址。不能指向 `localhost`，也不能直接用 IP 地址代替 CNAME 目标。

### 第 2 步：选一个好名字并检查是否可用

选择一个没有被占用的完整地址，例如：

```text
echo-yourname.is-a.dev
```

要求通常包括：

- 只能使用小写字母、数字和连字符
- 不能冒用他人商标或知名品牌
- 不能用于钓鱼、违法内容或误导性服务
- 需要有一个可联系的所有者信息
- 需要 GitHub 账号提交申请

在 is-a.dev 官网或注册仓库中检查同名记录是否已经存在。如果已有文件 `domains/echo-yourname.json`，就换一个名字。

### 第 3 步：在 Render 添加自定义域名

1. 打开 Render 聊天室服务详情页。
2. 进入 **Settings → Custom Domains**。
3. 点击 **Add Custom Domain**。
4. 输入刚才选定的完整域名，例如 `echo-yourname.is-a.dev`。
5. Render 会显示需要配置的 DNS 记录，通常是一条 CNAME。
6. 记录下 Render 给出的 **CNAME 目标主机名**，例如 `echo-chat-room-xxxx.onrender.com`。

此时 Render 可能显示域名尚未验证，这是正常的；等 DNS 记录生效后再回来验证。

> 免费套餐是否支持自定义域名、需要什么验证记录，以 Render 当前页面为准。如果平台要求额外 TXT 验证，也按页面提示添加。

### 第 4 步：Fork is-a.dev 注册仓库

1. 登录 GitHub。
2. 打开 <https://github.com/is-a-dev/register>。
3. 点击右上角的 **Fork**，得到自己的副本。
4. 在副本中进入 `domains/` 目录。
5. 点击 **Add file → Create new file**。
6. 文件名为：

```text
echo-yourname.json
```

文件名必须与申请的前缀一致。不要写成 `echo-yourname.is-a.dev.json`。

### 第 5 步：填写 DNS 申请文件

仓库模板可能更新，务必同时查看仓库中的示例文件和 `CONTRIBUTING.md`。常见格式如下：

```json
{
  "description": "Echo chat room",
  "owner": {
    "username": "your-github-username",
    "email": "you@example.com"
  },
  "record": {
    "CNAME": "echo-chat-room-xxxx.onrender.com"
  }
}
```

替换规则：

- `description`：简单说明用途，不要写无关广告。
- `owner.username`：你的 GitHub 用户名。
- `owner.email`：可联系邮箱，可以使用 GitHub 提供的隐私邮箱。
- `record.CNAME`：复制 Render 中显示的 CNAME 目标。
- 不要添加 `https://`、路径、端口或结尾斜杠。
- 如果 Render 显示多个记录，以平台页面为准；子域名通常只使用 CNAME。

### 第 6 步：提交 Pull Request

1. 提交新文件，提交信息可以写 `Add echo-yourname.is-a.dev`。
2. 回到原仓库，点击 **Compare & pull request**。
3. 填写申请理由，提交 PR。
4. 等待维护者审核。可能需要补充说明、修改格式或关闭 PR 后重开。
5. 审核通过并合并后，社区会自动创建 DNS 记录。

PR 合并不等于立刻生效，DNS 传播可能还需要几分钟到数小时。

### 第 7 步：验证 DNS

在 Windows PowerShell 中执行：

```powershell
Resolve-DnsName echo-yourname.is-a.dev -Type CNAME
```

或者使用公共 DNS 查询：

```powershell
nslookup -type=CNAME echo-yourname.is-a.dev 1.1.1.1
```

应该能看到指向你的 `*.onrender.com` 地址的 CNAME 记录。

如果查询不到，先检查：

- PR 是否真的已经合并
- 文件名和域名前缀是否一致
- JSON 是否有逗号、引号或大小写错误
- 是否还在等待 DNS 缓存刷新

### 第 8 步：回到 Render 完成验证和 HTTPS

1. 回到 **Settings → Custom Domains**。
2. 找到刚才添加的域名。
3. 如果已经出现 **Verify** 按钮，点击验证。
4. 等待状态变成 **Verified**。
5. Render 会自动申请并续期 TLS 证书，通常不需要自己申请 SSL。
6. 打开 `https://echo-yourname.is-a.dev/health`，确认返回 `{"ok":true}`。

HTTPS 证书可能需要额外等待几分钟。如果浏览器暂时提示证书错误，请先检查 Render 的自定义域名状态，不要急着反复删除重建。

### is-a.dev 的使用边界

- 免费域名由社区维护，存在项目停止、规则变化或记录被撤销的可能。
- 它不是可以卖给别人的独立域名资产。
- 通常一个申请只对应一个子域名，不能随意批量注册。
- 不要把它用于网银、身份认证、付费业务等高风险场景。
- 如果以后对稳定性有要求，建议迁移到自购顶级域名。

## 其他免费域名选择

### eu.org

<https://nic.eu.org/> 提供 `.eu.org` 形式的免费域名，但通常需要人工审核，等待时间可能是数周甚至更久。申请时通常需要提供名称服务器，配置流程比 is-a.dev 复杂。

一种常见做法是先用 Cloudflare 免费 DNS 接管域名，再在 Cloudflare 中给聊天室添加 CNAME。适合愿意折腾、能接受长时间审核的人，不建议作为第一次部署的首选。

### js.org

<https://js.org/> 面向 JavaScript 相关项目提供 `项目名.js.org` 子域名，通常需要通过 GitHub 申请。具体是否接受聊天室、需要什么项目条件，以官网当前规则为准。

### DuckDNS / No-IP 等动态 DNS

这类服务更适合「家里电脑或 NAS 自己有公网 IP、需要动态更新 DNS」的场景。它们通常不能直接替代 PaaS 的 CNAME 配置，也不保证适合 Render 这类平台。没有公网 IP 时，优先使用 Cloudflare Tunnel，而不是尝试端口映射。

### 关于“永久免费 .com”

真正的 `.com` 顶级域名需要向注册局缴纳费用，因此不存在可靠的“永久免费 `.com`”渠道。常见风险包括：

- “首年免费”或“首年 1 元”，第二年开始高价续费
- 需要绑定银行卡或自动续费
- 域名所有权并不在你名下
- 仿冒注册商窃取账号或支付信息
- 曾经提供免费顶级域名的渠道停止服务或无法转出

Freenom 等旧渠道长期不稳定，不建议把项目地址建立在上面。看到“免费 .com”广告时，先查注册商资质、WHOIS 和续费价格。

## DNS 与部署排错

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| Render 构建失败 | 仓库缺少文件、Node 版本过低 | 查看 Deploy Logs；确认根目录有 `package.json` 和 `server.js` |
| 部署成功但打开是 502/504 | 实例唤醒中、应用没有监听 `PORT` | 等待冷启动；确认使用 `process.env.PORT`；查看运行日志 |
| 页面空白或资源 404 | `public/` 目录未上传完整 | 检查仓库中是否有 `public/index.html`、`styles.css`、`app.js` |
| 状态一直显示“重新连接” | SSE 被代理或网络阻断 | 打开 `/health`，检查浏览器开发者工具的 Network/EventSource |
| 自定义域名一直 Pending | CNAME 未生效或目标写错 | 用 `Resolve-DnsName` 检查；确认 PR 已合并；重新添加域名 |
| 自定义域名显示证书错误 | TLS 证书仍在签发 | 等待 Render 完成验证和证书签发；确认没有混用 HTTP 资源 |
| 聊天记录突然清空 | 免费实例重启或重新部署 | 这是内存存储的预期行为；正式使用需接入数据库 |
| 浏览器提示 429 | 5 秒内发送超过 8 条 | 等待几秒再发；这是内置的频率限制 |
| 第一次访问特别慢 | 免费实例从休眠中唤醒 | 等待几十秒并刷新；长期在线需要付费实例或其他托管 |

### 检查 DNS 的实用命令

```powershell
# 查看 CNAME
Resolve-DnsName echo-yourname.is-a.dev -Type CNAME

# 检查健康接口
Invoke-RestMethod https://echo-yourname.is-a.dev/health

# 检查 HTTP 响应头
Invoke-WebRequest https://echo-yourname.is-a.dev/ -UseBasicParsing
```

## 上线前的安全清单

- 这是一个公开聊天室：任何获得网址的人都能进入。
- 昵称没有唯一性和强身份验证，别人可以冒用同名昵称。
- 不要发送密码、身份证件、住址、验证码等敏感信息。
- 免费域名和免费实例不提供可用性保证，不要用于重要业务。
- 如果要正式运营，至少需要登录、数据库、内容审核、举报和限流策略。
- 不要把 `.env`、私钥或真实用户数据上传到公开仓库。

## 推荐路线

如果只是想尽快把聊天室发给朋友：

1. 用 Render 免费实例部署。
2. 直接使用 `*.onrender.com` 平台地址。
3. 以后想要更好记的地址，再按 is-a.dev 教程申请免费域名。

如果要长期稳定运营：

1. 购买自己的 `.com` / `.net` 等域名。
2. 使用付费托管或云服务器。
3. 添加数据库、身份认证、审核和监控。
4. 配置自定义域名、HTTPS、备份和告警。
